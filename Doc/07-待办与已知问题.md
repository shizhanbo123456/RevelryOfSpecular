## 四、约定与备忘（写后续代码时遵守）
- 服务器↔客户端传输的类：`SC` 开头（服务器→客户端）/ `CS` 开头（客户端→服务器），序列化器写在同一文件内
- ScriptableObject 一律 `Info` 结尾
- 一个类内不影响理解的计算函数放最后，用 `#region//Local` 包裹
- 全局参数被动（复活速度等）开战一次性计算，不做成 Buff；僵尸刷新等级例外，按战斗剩余时间在刷新时实时计算（`BattleManagerPassive.GetZombieSpawnLevel`）
- 客户端只做表现，关键逻辑全部服务器计算
- **客户端逻辑一律进 `ClientLogicManager` 的子管理器**（普通 C# 类，继承 `ClientSubManager`）：能并入既有子管理器就别新建；UI 的数据来源仍是 `ClientEvent` 事件
- 事件订阅与解绑必须成对（`EventManager` 是静态的，只订阅不解绑会随场景重载累积）
- 服务器与客户端都需要的逻辑（如轨迹构建）写成双端共用的函数，不要各写一份
- **延时 / 重复调用一律用 `Timer.AddTimer`**（`Utils/MonoUtils/Timer.cs`，由 `Tool` 每帧驱动），禁止自己写计时字段
- 注释只解释"为什么"，不复述代码、不写变更历史，禁止大段注释
- **移动 / 速度的完整口径见《代码架构说明》"速度"节**（允许的五个来源 + 动画机地位相同）：游戏逻辑只触发动画与传参数，**不自己产生速度**
- **AI 的落点 = 覆写 `EntityData.TickAI()`**（虚方法，`BattleManager.UpdateAI` 每帧遍历调用；**不要往 `BattleManager` 里加类别分支**）。三条链：会移动/追击的 `ZombieEntityData`；固定周期施法的继承 `AutoCastEntityData`（每 `AutoCastInterval` 秒随机放一个技能）；玩家 AI 走 `PlayerEntityData.TickAI` → `PlayerAiController`（**攻守共用、不分叉**——目标选择只问"最近的敌对目标"，差异由 `HostileOf` 承担）。寻路**只借 NavMesh 算"往哪走"**，**不用 `NavMeshAgent`**（它会自己驱动 transform/速度），只用 `NavMesh.SamplePosition` + `CalculatePath` 这类"只算不动"的 API；工程装的是旧版 Navigation，**只需在服务器场景烘焙**，烘焙产物属 `Assets/Files/**`
- **玩家阵营 = `PlayerCampType` 三分类（攻/守/观战，进大厅默认观战），与实体阵营 `EntityCamp` 分离——不要给实体阵营加观战，也不要在服务器内部用 -1 表示"未选队"**
- **`Entity/Anim/**` 动画模块由你自行开发，我不改动**
- ⚠️ **`Assets/Files/**` 与场景/预制体不在本仓内**（本仓 = `Assets/Scripts`）→ 这些改动**无法提交、不受版本控制**，相关资产事务由你在 Unity 内自行处理
