AI 实时操控交互（命令行 + Lua）
====================================================

一、总体架构
----------------------------------------------------

控制权：决策在客户端，执行在服务器。
  客户端：命令行（外部 AI 的入口）+ Lua（状态机脚本 + 命令行拓展脚本）
  服务器：意图转发 + 行为层，不做任何决策

三条链路：
  1. 命令行 → 本地 C#（房间流程、聊天、查询类，不联网也能取）
  2. Lua 状态机 → 本地 C# → 意图上行 → 服务器意图转发器 → 行为层
  3. 服务器事件 → 中断原因列表 → 命令行「等待中断」整批返回

行为层复用现有三件套，不新写状态机：
  BehaviorArbiter + IBehaviorHost + IdleBehavior / MoveBehavior / AttackBehavior
  停步、朝向、动作未播完不许切（AttackBehavior.CanInterrupt = !host.IsActing）全部归行为层
服务器侧只新增一个「意图转发器」，做「客户端意图 → BehaviorArbiter 请求」的翻译，不含决策

复用边界：
  不复用 GM 指令通道（CSGm / ExecuteGm）
  不复用上帝视角协议（CSGodViewArea 等）
  不复用 RobotAi（人机决策机）及其技能栏
  复用项目基础设施：BehaviorArbiter / IBehaviorHost / Behavior、EntitySkillController、Timer、EventManager

坐标与时间口径：
  位置只给 XZ（地形是平的），单位米，地图范围 0 ~ Landscape.MapSize
  朝向为 yaw 度数，0° = +Z，与 PlayerEntityData 的 moveState.yaw 同口径
  不传高度：服务器按地面吸附

交互语义：
  除「等待中断」外，所有命令立即返回
  失败不返回原因：失败提示走「提示消息」中断，AI 中断后自己看
  移动不做「到达」中断：中途大概率遇到敌人而中断，到没到由 AI 自己判位置

战斗期分工：
  战斗节奏快，命令行不参与操作，一律由客户端 Lua 状态机驱动
  命令行只在战斗外做编排、查询与调试

二、命令行可控内容
----------------------------------------------------

通用（不联网也可用，除注明）
  发送聊天(channel, content)
      联网后有效；channel 0 全频道 / 1 阵营频道
      落点：NetworkManager.SendChat(CSChat)
  读取聊天记录(数量 N)
      返回最近 N 条，每条：消息类型（全局 / 阵营 / 系统）、发送者阵营、发送者名称、内容
      收发都要：自己发的（本地回显）与他人的都算
      系统消息来自 SCPrompt / SCBattleEvent，不含伤害飘字
  获取本地玩家名称
      落点：ClientSelection.playerName
  等待中断(可加定时)
      唯一的阻塞命令：先取中断原因列表的积压，非空立即整批返回；空则挂起等待
      带定时时，超时也作为一种中断原因返回
  设置可选中断(开关集合)
      全局生效，未开启的可选中断不记录（避免列表被无用条件灌满）

Home
  选择角色(进攻方下标, 防守方下标)
      落点：ClientSelection.selectedAttackIndex / selectedDefenseIndex
      进房时随 CSLobbyPlayerInfo 上报，含等级与名字
  连接服务器(ip)
      落点：NetworkManager.TryConnect → 成功后 EnterWorld()
      失败提示由服务器/本地弹提示，AI 通过「提示消息」中断看到
  设置本地玩家名称(名称)
      落点：ClientSelection.playerName，进房时上报

Lobby
  选择阵营(camp)        0 进攻 / 1 防守 / 2 观战
  准备(ready)           true / false
  离开房间
      落点：NetworkManager.SendLobbyUpdate(CSLobbyUpdate) / ExitWorld()

Battle
  站立                      停步并保持朝向，见「四、意图与行为层映射」
  移动到目标(x, z)           走向静止坐标，到达后停在原地
  攻击珊瑚                  攻击最近的珊瑚（内部等价于「攻击目标(珊瑚 id)」）
  释放指定技能(skillId)      不走意图，直接让行为层停步+施法，见第四节
  计算移动路程的预计路径长度(x, z)
      客户端用 NavMesh 算；返回路径长度与是否可达
      仅作预估：客户端与服务器是两份独立烘焙数据，可达性以服务器的「移动失败」为准
  激活客户端 lua 状态机      激活时自动重载一次状态机脚本
  停止客户端 lua 状态机      停决策 + 发一次站立（避免角色保持上一个动作继续跑）
  执行 lua 拓展内容(命令名, 参数…)
      调用 lua 拓展脚本里注册的命令，见第七节
  获取小地图显示的实体
      返回小地图当前实际显示的点：实体 id、类型、阵营、坐标、白眼标记
      口径 = 小地图显示内容本身（已按显示半径裁剪、已剔除超时与消亡）
  截屏
      返回文件路径 + 当前位置 + 朝向；图片单独存盘
      会临时开启相机渲染至少一帧再截（与「设置相机开关」互斥）
  获取技能列表（含库存）
      槽位内技能：技能 id + 当轮恢复进度 + 剩余库存（-1 = 无限）
      槽位外技能：只给 id 列表
  设置技能栏的技能(id 列表)
      服务器校验后回推快照，本地不预演
      作用不止于按键顺序：栏外技能冷却冻结不恢复，故「进栏」= 让它持续恢复
  设置相机开关(开 / 关)
      指是否启用相机渲染（关闭省帧），不是切换视角模式
      关闭时坐标换算、射线的能力不受影响：停渲染不停 Camera 组件
  守护点血量信息
      四个守护点 main / sub1 / sub2 / sub3 的 0~100 开采进度（被打掉的血量百分比），
      不是实体生命值；是否被摧毁看 StatueDestroyed 事件
  本地玩家血条和技能状态
      血量当前/上限、buff 列表、技能槽位与冷却进度、库存

三、Lua 可控内容
----------------------------------------------------

操控服务器状态机(意图, 目标)
  意图集合：站立 / 移动到位置(x, z) / 攻击目标(entityId) / 停止
  「攻击珊瑚」为命令别名，内部解析成「攻击目标(最近珊瑚 id)」
  敌我单位与珊瑚都走「攻击目标」，不再按类别分命令
  意图按需下发，不逐帧发：由 C# 侧比较后只在变化时上行，Lua 每帧调也不会刷包

释放指定技能(skillId)
  不经过意图与决策，直接让行为层停步 + 施法（见第四节）
  技能合法性全部由服务器的 EntitySkillController 收口，Lua 不需要自己算冷却

信号发出(消息类型, 可选位置)
  对应现有 8 种快捷消息：集结 / 解除信号 / 进攻 / 危险警告 / 请求上报 / 上报状况 / 争夺中立 / 请求护送
  位置缺省表示不携带（动态锚点，跟随发送者）

触发中断(原因文本)
  Lua 主动往中断原因列表写一条，供下一次「等待中断」取走

命令行拓展
  Lua 侧注册命令，供命令行按需调用，见第七节

四、服务器：意图转发器与行为层
----------------------------------------------------

职责：只把客户端意图翻译成 BehaviorArbiter 的请求，不做任何判断、不索敌、不选技能。

每帧：
  1. 收到上行意图 → 立即写入请求（不等下一拍）
  2. arbiter.Tick(deltaTime) 每帧执行
  转发层不做节流：ThinkInterval 必须为 0，否则命令最多延迟一个间隔才落到行为层

意图 → 行为层映射（行为层共三个行为：Idle / Move / Attack）
  站立            → RequestIdle(朝向点)
  移动到位置      → RequestMove(point)         请求只在变化时下发，行为层只在请求变化时 MoveTo
  攻击目标(id)    → RequestAttack(target)      停步 + 面朝 + 按技能栏节奏出手
  停止            → RequestIdle() 并清空意图

释放指定技能：
  走独立的 AI 专用协议（CSAiSkillCast → ReceiveAiSkillCast），与键盘技能键分开：
  接管期间键盘包被服务器丢弃，不影响这条通道
  不算意图，属于插队行为：停步 + 面朝（若有目标）+ TryUseSkill(skillId)
  释放后保留原意图，下一拍回到原行为（放技能不打断走位意图）
  技能被拒（未持有 / 沉默 / 强控 / 冷却）：由服务器的既有提示与技能快照处理，Lua 不另做判断

攻击类不判距离：
  EntitySkillController.TryUseSkill 没有施法距离门闸，超距也会放出去（按射程给落点）
  「攻击目标」只做停步+面朝+出手，走到射程内是客户端状态机的职责

移动失败要回传：
  MoveBehavior 在目的地算不出路时会 Stop + NotifyStuck
  转发器把它转成一条中断原因（移动失败：目标不可达），否则客户端会对着走不到的点反复下命令

无命令 = 保持最后一个动作（设计如此，服务器不做超时兜底）：
  行为层的 None 语义是「本拍没意见，保持当前动作」，停发命令后角色会一直保持上一个动作
  需要停下时由客户端显式下发「站立」：停止状态机与 lua 崩溃路径已带站立下发，断线则保持到重连

实现注意：
  1. 被 AI 操控的玩家实体不能标 robotControlled（那是 RobotAi 的入口，会连带技能栏与快捷消息），
     需要独立开关；但 OnTickMove 里「自动移动分支」（FaceDirection + SetMoveInput）要复用同一份，
     建议把该分支的判据泛化为「自动驱动」，不要复制一份移动逻辑
  2. RequestIdle 目前只接受实体作为朝向目标，「站立并面向某个点」要补一个点重载
  3. 转发器的 Tick 挂在 PlayerEntityData.TickAuto()，与 RobotAi 同层互斥
  4. AI 接管期间服务器丢弃该客户端的键盘输入（ReceiveInput / ReceiveSkillCast 各一处判断），
     接管状态记在会话上（BattleManager.AiClients）：复活重建实体时按会话恢复，只在玩家退场时清除

五、默认 Lua 状态机（实现于 AiInterface/Lua/state_machine.lua）
----------------------------------------------------

状态：站立、移动到位置、攻击敌人、逃跑、寻找珊瑚、追击珊瑚、攻击珊瑚
参数（脚本顶部常量，暂定值，实测后调整）：
  追击阈值 12m ｜ 脱离阈值 18m ｜ 攻击性 0~1（0.5）｜ 攻击距离 8m ｜ 意图重发节拍 0.2s

规则（每 0.2s 一拍，感知全部来自小地图即雷达半径内）：
  血量 < (1 − 攻击性 × 0.7) 且附近有敌人 → 逃跑：朝背离敌人撤到脱离阈值外，拉开或脱战即结束
  敌人进入追击阈值 → 攻击：先 move_to 贴近，进攻击距离后每拍重发 attack（持续出招的节拍）
  敌人拉出到脱离阈值或消失 → 回站立
  视野内有珊瑚 → 攻击距离内 attack、距离外 move_to（真敌人的判定在珊瑚之前）
  都没有 → 站立
敌我判定 = 阵营不同且非中立（僵尸属防守阵营，天然被进攻方当敌人）
注意：状态机激活期间，命令行的 站立/移动到位置/攻击珊瑚 会被状态机节拍覆盖；手动控制先停状态机

六、中断系统
----------------------------------------------------

结构：
  C# 端维护一个中断原因列表，每条 = 类型 + 若干上下文段（多段字符串）
  列表有界（16 条），同类型在 2 秒窗口内连续触发合并为一条：保留首次时间、最后一次的值与次数

语义：
  任何已开启的中断条件成立 → 追加一条，不打断当前动作、不打断 Lua 执行
  「等待中断」执行时先取积压：非空立即整批返回并清空；为空才挂起，下次有中断时一次取走全部
  未开启的可选中断不记录，避免列表被无用条件灌满
  这样 AI 思考期间发生的中断不会丢，也不会被同一个条件反复打断

每条原因必须自带上下文（AI 靠它判断现场，不再单独查询）：
  遇到敌人        实体 id、类型、阵营、坐标、距离、同屏数量
  提示消息        notice id + 已解析文案（含技能被沉默/被控制/冷却中）
  昼夜切换        现在白天/夜晚、当轮进度
  获得技能        技能 id 列表、来源（掉落 / GM / 复活继承）
  战斗开始/结束   我方阵营、实体 id、结算结果
  定时            等待时长与超时点
  lua 报错         脚本名、行号、错误消息
  移动失败        目标坐标、失败原因
  特殊能力播报    技能 id + 名称
  中立单位刷新    中立单位实体 id、坐标

中断条件与数据来源：
  命令行结束      本地（命令返回）
  定时            本地（Timer）
  聊天@           本地（OnChatMessage + 文本匹配）
  lua 触发        本地（Lua 主动写）
  lua 报错        本地（LuaEnv 错误回调）
  战斗开始/结束   本地（OnBattleStart 10210 / OnBattleEnd 10211）
  他人信号        快捷消息（OnQuickMessage 10313，按 QuickMessageType 区分，带发送者与可选坐标）
  遇到敌人        本地（小地图出现新的敌对单位；0.5s 检查间隔 + 中断列表同类型合并）
  特殊能力播报    SCBattleEvent.SkillBroadcast(10)，textId = 技能 id
  中立单位刷新    SCBattleEvent.NeutralStatueRespawn(4)
  昼夜切换        SCBattleEvent.Nightfall(5) / Daybreak(6)
  获得技能        OnSkillBarRefresh(10221)；该事件也被选栏与快照触发，需按持有表变化去重
  提示消息        OnShowPrompt(10305) + SCPrompt（notice.csv id）

七、Lua 命令行拓展
----------------------------------------------------

用途：让 Lua 按需扩展命令行工具，外部 AI 通过命令行调用这些命令

注册：Lua 侧向宿主注册命令（命令名 + 处理函数），处理函数接收参数表并返回字符串
调用：统一走「执行lua拓展内容 <命令名> <参数…>」，与内置命令同一套解析
枚举：提供一条命令列出当前已注册的拓展命令，供 AI 先查询再调用
重载：重载拓展脚本时清空并重建注册表；正在执行的拓展命令先跑完再重建
报错：拓展命令抛错进「lua 报错」中断，只记录与上报，不影响状态机与其他命令继续运行

九、待确认与不一致
----------------------------------------------------

1. 「释放指定技能」的强停语义已按「插队、保留原意图」实现，若实际要「真停」需改写第四节。
2. 「重载命令行拓展」：拓展脚本现按需加载、随「激活lua状态机」整份重载；
   运行中单独重载拓展的入口仍缺，需补一条命令或并入激活流程。
3. 「他人信号」按快捷消息（8 种）理解，与「聊天@」区分；若还包含其他信号需补充来源。
4. 系统消息范围按 SCPrompt + SCBattleEvent 理解，不含伤害飘字；需确认。
5. 小地图缓存由命令行自建（订阅 OnMinimapUpdate + minimap_entity_timeout 超时剔除），
   未复刻 UI 的显示半径裁剪，边界点位可能比小地图多，需实测对齐。
6. 安全：服务器是否校验「该客户端被授权做 AI 操控」（当前设计默认不校验，任何客户端都能发意图）。

十、文档内容（给 AI 的静态资料）
----------------------------------------------------

随程序提供，不通过命令行查询（命令行只查实时状态）：

角色属性
  角色 id / 阵营 / 名称、初始血量、移速、视野、武器槽位数量、初始技能、体型与命中半径、霸体等级

技能属性
  技能 id / 名称 / 品质、冷却、存储上限、射程、索敌夹角、索敌半径、伤害倍率、是否需要目标、
  释放动作与动画时长

常用位置
  副守护点 ×3、主守护点、水晶雕像点、中立雕像候选点、进攻方出生/复活点、防守方出生/复活点
  （均为世界坐标 XZ，来源 LandscapeSpawns）

所有可被 lua 调用的内容
  可读：自身状态（位置/朝向/血量/buff/技能冷却与库存）、小地图实体、守护点进度、昼夜
  可写：意图（站立/移动到位置/攻击目标/停止）、释放指定技能、信号发出、触发中断
  读调用零成本、可每帧调；写调用只在值变化时上行
