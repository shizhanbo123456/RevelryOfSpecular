# 05 UI（FGUI 界面接线说明）

> 配套：`Assets/Resources/GUI/Main_fui.bytes`（包名 Main）+ `ScriptsGenerated/Main`（生成类，命名空间 **Ros.UI.Main**，引用需 `using Ros.UI.Main;`）。
> 本文档 = 字段含义 / 档位表 / 接线映射的参考。逻辑接线在 `UI/UIManager.cs` + `UI/PageBase.cs` + `UI/Logic/*`。

## 一、页面根与整体结构

| 部件 | 组成 |
|---|---|
| **UI_HomePanel** | 单页（无 m_page 控制器）：m_connectPanel(UI_HomeConnect) + m_playerInfo(UI_PlayerInfo) + m_characterList(UI_HomeCharacterList)。角色选择浮层由代码控显隐（默认隐藏，「选择角色」打开，底框关闭按钮收起） |
| **UI_LobbyPanel** | m_mainView(UI_LobbyMemberList) |
| **UI_BattlePanel** | m_world_element_container(UI_empty_container，最底层，场景 UI 挂它) + m_skillList + m_PlayerBar(UI_PlayerHealth) + m_Minimap + m_eventBanner + 复活进度（m_showRegenerationBar + m_regeneration_progressbar）+ m_barPanel(UI_BattleBarPanel，守护点 4 条) + m_batleInfoPanel(UI_BattleInfoPanel，时间/昼夜图标/三方人数/设置按钮) + m_settings_panel(UI_SettingsPanel) + m_onlook 控制器 + m_onlookComboBox + m_showBanner 转场 |
| 全局子界面（挂 GRoot，不挂页面） | SettlementView(UI_BattleResult + Detail + DetailItem)、ConfirmView(UI_ConfirmPanel，全屏拦截层在面板内部)、加载界面(UI_LoadingPanel)、全局飘字(UI_NoticePanel)、ChatPlugin(UI_ChatPanel)、GmPanel(UI_GmPanel) |

- 页面统一由 `PageBase` 管：`Root.scale = Screen.height / 1080`，尺寸取 `1080 * (屏宽/屏高) × 1080`；世界坐标 → 面板坐标用 `PageBase.WorldToPanel`（Unity 左下原点 ↔ FGUI 左上原点翻转）。
- **场景 UI 层**：`m_world_element_container` 是战斗面板最底层子物体，实体血条与战斗飘字都挂在它上面，所以被所有 HUD 元素遮挡；面板坐标经 `BattlePage.ToWorldLayer` 换成容器局部坐标。容器需 位置(0,0)、缩放(1,1)、overflow = visible，否则血条会被裁。技能 / buff 悬浮提示仍挂面板根，保持最上层。
- **通用底框关闭**：`PageBase.BindFrameClose(UI_panel_2 frame, GComponent target)` —— 底框自带关闭按钮 `m_close`，点了把 target 收起；显示关闭按钮的面板直接调它，不必各配按钮。
- 切页：`UIManager.TurnPage(PageType.Home/Lobby/Battle)`，由 `ClientEvent`（OnConnect / OnBattleStart / OnRestartGame / OnExitWorld）驱动；切页时自动收起未决的确认弹窗。

## 四、协议依赖

- `SCEntityDisplayInfo`：hasHealth → health/maxHealth；**hasBuffs → buffs（type+level，type 即 effect.csv 主键）**；hasSkills → skills（仅持有技能 id，无冷却/库存；只发给该实体所属客户端）。血条、名牌、buff 列表全部来自这一条包
- **哪些实体有头顶血条由 `entity.csv` 的「显示血条」列决定**（留空/0 = 不创建，1 = 创建）：`BattlePage.OnEntityDisplayUpdate` 按 `EntityConfig.GetByCategory(info.type).showHealthBar` 判断，不再按实体类别硬编码；名牌仍只给进攻/防守双方角色
- `SCBattleEvent`：type 决定 EventIcon 档位与条目版式；textId/textId2 为数字 id（<10000 查 notice.csv，≥10000 为玩家名，clientId = id − 10000）
- `SCCombatLabel`：amount（伤害量或治疗量）+ type（`CombatLabelType` 页号）+ targetId + 可选 hitPos
- `SCCampAliveCount`：attacker/defense 的 alive+total + spectatorCount
- `SCMinimapEntity` / `SCMinimapRadius`
- `SCLobbyInfo`（members: camp/characterIndex/ready）+ `SCLobbyPlayerName` + `CSLobbyPlayerInfo`（玩家名上报）
- 加载期：`SCLoadingStart` → `SCLoadingPrepared` → `CSLoading*Request` / `SCLoading*Response` → `CSLoadingComplete` → `SCBattleStart`；战斗期的玩家名与玩家↔实体关系全部来自这套数据
- `SCReviveInfo`（复活进度）、`SCPlayerEntity`（玩家 ↔ 实体映射，-1 = 无实体）
- `EntityPlayerManager.TryGetAnchorPos(id, EntityAnchor, out pos)`：名牌/血条走 `Bar`，战斗飘字兜底走 `LabelFallBack`

## 五、玩家阵营（四分类）

- 枚举 `PlayerCampType`：`Attack=0 / Defense=1 / Spectator=2 / Neutral=3`，数值即协议值、也即 `PlayerCampIcon.m_player_camp` 与 `ChatItem.m_camp` 的档位。
- 与实体阵营 `EntityCamp`（位标志：Attack=1 / Defense=2 / Neutral=4 / Prop=8 / Zombie=16 / DefenseTower=32）分离：观战与中立只是玩家归属，实体侧没有观战实体。
- 实体血条显示时由 `BattlePage.ToPlayerCamp` 转换：攻/守原样，防御塔（`DefenseTower`）归防守方，其余（中立雕像、珊瑚、场景物件）一律取「中立」档；敌对只在攻/守双方之间判定，防御塔由 `BattlePage.IsEnemyCamp` 单独处理——进攻方看到为敌、防守方看到为友。
- 大厅当前提供攻/守/观战三个块，玩家还选不到中立；服务端开局判定、AI 分配、加载分包与视野仍按攻/守/观战三分类处理。

## 七、聊天

**需求**：两种频道——全频道（所有人可见）+ 阵营频道（仅同阵营）；联网状态（大厅与战斗）都可用，首页不显示；自己的消息本地立即回显；面板无标题栏、无关闭按钮，靠联网状态自动显隐。

**ChatPanel 成员**

| 成员 | 类型 | 说明 |
|---|---|---|
| m_show_channel_menu | Controller | 0 收起频道按钮（大厅）/ 1 展开（战斗） |
| m_input | GTextInput | 单行输入框，`onSubmit` 等价于点发送 |
| m_btn_send | GButton | 发送 |
| m_content | GList | 聊天列表；`itemProvider` 按当前页签返回 UI_ChatItem（全频道 / 阵营频道）或 UI_EventItem（系统消息），`overflow=scroll` |
| m_btn_allChannel / m_btn_campChannel / m_btn_systemInfo | GButton | 页签 = 频道（0 全频道 / 1 阵营频道）+ 系统消息页签（只读，不参与发送），选中态用 `GButton.selected` |
| m_fold | Controller | 0 展开 / 1 收起 |
| m_btn_hide / m_btn_show | UI_btn_chatShowHide | 收起 / 展开按钮（组件的 m_side 控制器未设，走默认朝向） |

**ChatItem 成员**：m_side（0 他人 / 1 自己，只切头像与阵营图标的 XY）、m_camp（0 攻 / 1 守 / 2 观战 / 3 中立）、m_headIcon、m_player_name、m_content（autoSize=height，自己消息右对齐）。

**数据流**

1. `UIManager` 启动创建 ChatPanel（ChatPlugin 持有，默认隐藏）；`OnConnect` 显示并清空，`OnExitWorld` / `OnRestartGame` 清空并隐藏。
2. 发送：`m_btn_send.onClick` / `m_input.onSubmit` → 取文本，去空白后非空、长度 ≤50、1s 内只发一条（超长飘字提示，空消息与冷却静默忽略）。
3. 本地回显：先入表（`m_side=1`、阵营=自己），清空输入框，滚到最新。
4. 上报：`NetworkManager.SendChat(CSChat{channel, content})` → 服务器 `BattleManager.ReceiveChat` 组装 `SCChat`（补 senderClientId / 名字 / 阵营 / characterIndex）后 `SendTo.Everyone` 广播。
5. 下行：`ClientReceiveChatLocal` → `ClientEvent.OnChatMessage` → ChatPlugin 过滤（自己发的忽略；阵营频道且发送方阵营 ≠ 自己且未开 GM「敌方对话」时忽略）。
6. 渲染：写 `m_side` / `m_camp` / 名字 / 正文 / 头像；列表只保留最近 50 条，超出从头部移除后重设 `numItems`。

**界面行为**：联网进大厅即显示，切战斗仍在；断开/离开房间清空并隐藏、复位为展开态；折叠后按新尺寸重新贴左下角（面板整体缩放 = 屏幕高/1080，x=0 贴左，底边距屏幕底部 50px）。

## 八、FGUI 运行时库补丁

`Assets/FairyGUI-unity-master` 是直接放在工程里的 FGUI 运行时源码，其中有一处项目自己的改动，不属于 FairyGUI 官方代码。**重新下载或覆盖该目录后必须重新打上，否则回弹会重新出现。**

| 文件 | 改动 | 效果 |
|---|---|---|
| `Scripts/UI/UIConfig.cs` 的 `defaultScrollBounceEffect` | `true` → `false` | 滚动面板默认关闭回弹：拖到任意一端即硬停，不会被拉出空白再弹回；鼠标拖拽滚动本身保留 |

机制：`ScrollPane.Init()` 用该默认值初始化 `_bouncebackEffect`，只有导出包里显式带「回弹 = true」标记位的面板才会覆盖它（`ScrollPane.Setup_BeforeAdd`）。要单独打开某个面板的回弹，就在该面板上写 `scrollPane.bouncebackEffect = true`。
