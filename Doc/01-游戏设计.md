## 一、项目概述

**[A]** 本项目为"多人非对称对抗 + MOBA 式地图攻防 + 局内技能构筑"玩法。

**[A]** 多个相对较弱的进攻方玩家，对抗防守方玩家（防守方人数不限定，见第三章）。

**[A]** 双方围绕多个外围防守目标和一个最终核心展开攻防；所有玩家一起开始、一起结束战斗。

**[A]** 玩家通过近战动作、主动触发技能直接参与战斗；局外养成只保留角色等级成长（角色随玩家等级自动解锁）。

**[A]** 尽可能减少难以感知的纯数值 Buff，强调可从画面和操作中直接理解的状态变化。

**[A改]** 标准对局推荐 4 进攻方 vs 1 防守方，但实际开发中**不限制具体人数**，双方均有人即可。

**[A改]** 单局时长 **10 分钟**。

## 二、动画与攻击事件 [A]

**[A]** 玩家输入首先请求一次攻击并播放本次攻击绑定的动作；实际伤害判定、子弹生成、投掷物脱手或悬浮武器开火，在动作的指定攻击事件到达时执行。

**[A]** 一个动作可以包含一个或多个攻击事件，用于连续攻击或多段发射。

**[A]** 动画事件只表达"本次攻击到达触发时机"，具体生成哪种攻击由当前动作、当前技能和本次请求决定，不把具体技能逻辑硬编码进动画文件。

**[A改]** 动画被打断后，尚未到达的动画攻击事件不再生效——**由动画状态机处理，无需代码额外处理**。

**[A改]** 攻击上下文绑定的实现方式：每次触发时向角色动画组件传入新的事件（确保旧的事件已撤销）。各动作的攻击事件数量与用途由用户后续记录在角色动画组件中。

**[A]** 部分弹幕技能允许不播放角色施法动作；使用施法动作的技能可绑定短/中/长施法动作，并在事件帧生成子弹。

**[A改]【架构原则】** 客户端中给玩家看到的内容只需保持大致合理，**所有关键判断全部在服务器**；服务器和客户端都需要播放动画（服务器上不渲染、不实例化角色，只是空壳 prefab，用来触发动画事件）。

**[A改 2026-09-12]【动画同步】** 服务器与客户端**共用同一份动画状态机资产**，同步标识用**动画状态的完整路径 hash**（两端一致）；客户端据此定位片段，并按服务器给的**归一化播放进度**继续播放，**同一片段不重播**（让本地动画连续推进，避免每帧被拽回开头）。客户端**不需要也不传递角色类型**——播哪一套动作（女 / 男 / 僵尸…）完全由服务器决定。

## 三、游戏流程与房间 [A]

### 3.1 流程 [A]

```text
加入服务器（单个服务器 = 单个房间，无匹配功能）
→ 初始界面选择角色
→ 进入组队阶段（选角与组队同时进行，房间中可随时调整角色）
→ 双方人数均 > 0 时可开始游戏（不自动分配阵营，玩家自行商议选择）
→ 全员准备，3 秒倒计时
→ 加载阶段（客户端加载界面；逐步拉取玩家/AI 名单，加载完成的客户端才进入战斗视图）
→ 正式战斗
→ 达成胜负条件
→ 全员同时结算角色经验
→ 返回组队阶段
```

### 3.2 房间与阵营 [A]

**[A改]** 无阵营意向、无 PVP/PVE 队列、无自动 AI 补位：**房间中任意玩家可自由编辑双方的 AI 玩家数量，数量不限制**。

**[A改]** 不自动分配进攻/防守：组队时手动选择阵营；双方人数都 > 0 才能开局，否则无法开启游戏，由玩家自行商议。

**[A改]** 无手动解锁：玩家等级达标后角色自动解锁；无匹配功能，只有加入服务器。

**[A]** 倒地救援机制**完全不存在**（已从策划案彻底删除）；玩家死亡即进入复活等待。

**[A]** 多名玩家协作，单体能力弱于防守方。

**[A改]** 推进路线（争夺资源→击破生物防御→拆外围守护点→攻击中心）仅为大致节奏，**非硬性流程**，玩家可不按此打。

**[A改]** 不做定位区分（2026-09-06 拍板），玩法由技能池与玩家自行摸索。防守方同样不设定位标签。

**[A改]** 防守方**不限定 1 人**，队伍人数由玩家自由安排；防守方基础战斗能力和战略影响力强于单个进攻方角色。

**[A]** 防守角色"少而精"：每角色 = 独特主动技能 + 独特被动 + 独特大招；**不设定位标签**，玩法由玩家自行摸索。

**[A]** 防守方"能力效果池"（主动池/被动池/大招池）为设计阶段的概念；6 角色技能已定稿（见第五章），效果池中未被采用的条目转入 11.3 总表"效果池（待分配）"。

**[A]** 防守方宗旨 = 守护更多守护点而非杀敌（杀敌仅作为对局得分的小因素）。

**[A改]** 防守方机动性强于进攻方（移速属性已删除，机动性差异改为动画/位移技能表现，**载体待重新设计**）。

**[A改]** 资源来源：**攻守双方摧毁珊瑚均可正常获得武器**（同一逻辑，见第七章）。

**[A改]** 技能使用方式：**技能槽快捷键直接触发 = 全游戏通用技能使用方式**（U I O L H Y 对应槽位 1~6，非防守方专属；2026-09-06 拍板）。

**[A改]** 每个角色都有**技能槽位属性**；防守方固有主动技能和大招**也占用槽位**。

**[A]** 僵尸相关技能（召唤小型尸潮、精英僵尸军队等）供防守方角色使用；**僵尸本体为独立阵营（Zombie），只以进攻方为敌**；"提升所有僵尸刷新时的等级"类被动为防守方阵营级增益。

## 六、防守目标 [A]

### 6.1 守护点（瘟疫信标）

**[A]** 地图 = 3 个外围守护点（矮瘟疫信标，分布不同路线）+ 1 个中心守护点（高瘟疫信标，位于防守区域）；守护点不可采集。守护点位置列表记录于**地形组件 LandscapeSpawns**（置于地形预制体内）。

**[A]** 中心守护点数量分层减伤：每个存活的外围守护点提供 25% 减伤（3 全在=75%，全拆=0）；中心不无敌、可直接攻击，形成"先拆外围 vs 直捣黄龙"的战略分叉。

**[A]** 减伤状态表现为护盾叠层（75%=3 层 / 50%=2 层 / 25%=1 层 / 0%=无）。

**[A改]** 无回血原则**仅约束守护点**（确保进攻方进度不可逆）；防御塔等其他单位不在禁止范围。

**[A改]** 防守方 HUD **常驻显示每个守护点血量**；**无预警机制**，防守方通过血量变化自行判断哪个守护点正在被拆。

### 6.2 瘟疫树（中立单位）

**[A改 2026-09-22]** 中立单位，双方争抢。**「攻占」= 把树打死**（树本身不属于任何一方，死后消失）：
- **归属**：把树**血量清零的那一次攻击的攻击者**获得「瘟疫祝福」；**被 Buff / DoT（固定数值伤害）打死的没有归属**，不给任何实体加成
- **奖励内容**：**伤害增加 75% + 伤害减免 25%**，持续 **30s**，作用于获得者**的所有技能**（含防守方主动 / 大招）
- **刷新时序**：开战后 **30s** 刷第 1 棵；此后每次树被打死，**60s 倒计时**结束后在候选点随机刷新一棵

> 2026-09-22 更正：原「攻占后技能冷却恢复速度翻倍，持续一段时间（细节待定 [C]）」作废 —— 奖励改为伤害增益；**全项目不存在"技能冷却恢复速度倍率"机制**。

**[A改]** 瘟疫树为中立，不属于任何阵营，**不提供视野**。

**[A改 2026-09-08]** 瘟疫树**主动攻击**：对进入攻击范围的**任何**单位自动索敌施放技能（中立无友方，对进攻方与防守方均敌对，谁靠近打谁）；技能走全实体统一技能模型（见 13.1），施法行为由 store / CD / 索敌范围等配置调节。

## 十一、状态与 Buff 系统

### 11.1 Buff 设计原则 [A]

1. 永久数值变化属于角色属性，不作为 Buff 显示。
2. 技能经验直接加成伤害，不堆叠为 Buff 图标。
3. 昼夜产生的阵营规则使用统一昼夜状态表达。
4. 只保留能从画面或操作中直接感知的状态；玩家无法理解的变化不做成独立 Buff。
5. 影响全局参数的被动（复活速度、僵尸刷新等级等）开局一次性计算，**不进 Buff 系统**；如有特殊能力需要在战斗中调整，也可以战斗中修改。
6. 全局无回血原则**仅约束守护点**；其他单位的回血类效果不受此限制（如"塔缓慢回血"闲置效果）。

### 11.2 分类框架 [C 暂定]

护盾类 / 属性调整类 / 机制调整类 三类框架**暂定**，待 Buff 系统详细设计后定稿。

### 11.3 Buff 清单（总表）

> **Buff 的类型、效果、来源、特征与特效映射，只在《03-技能与Buff总表》二章维护**，本文件不重复列。
> 本策划案只保留规则：叠加语义（默认「移除旧的再添加」；叠层 = 等级累加 + 时间刷新；独立 = 每层独立计时）、每个 Buff 必带等级与持续时长（无限 = 极大值）、强控期间动画停止且霸体等级立即降到最低、属性修改类 Buff 只改属性不改其它状态。

## 十三、技能系统 [A]

### 13.1 技能统一模型

**[A]** 技能三要素：①武器显示（可选，**漂浮在角色两侧**）②释放动作（可配置）③释放效果（必须）。

**[A改 2026-09-12]【武器显示（悬浮武器）完整规则】**
- **常驻漂浮**：凡是配了武器的技能，其武器**常驻漂浮在角色身边**（不是握在手里）。漂浮位置是**实体两侧固定的多个挂点，共 8 个（左右各 4：右前 / 左前 / 右中 / 左中 / 右后 / 左后 / 右下 / 左下）**——挂点数量多于技能槽位数上限，**技能槽 i 的技能用第 i 个挂点**。
- **近战类才到手**：近战类技能会临时把武器**从漂浮位拿到手上**，攻击动作结束时归还漂浮位；其余技能（远程 / 辅助 / 投掷等）**全程漂浮**。没有攻击动作的技能不手持。
- **远程从武器处发射**：远程技能的子弹出**本技能所在槽位的悬浮武器位置**发出；本身没有武器的单位（防御塔 / 瘟疫树等）回退到自身碰撞体上部的默认发射点。
- **投掷类**：把武器扔出去的技能只抛出一个**外观副本**，不影响该武器在漂浮位的显示。
- **零挂点配置**：漂浮位置是**相对实体根物体的固定本地偏移**，因此**任何实体都成立**（含没有动画组件的非人形单位：珊瑚 / 防御塔 / 瘟疫树 / 守护点），**不需要在预制体 / Inspector 上配置任何挂点**；客户端显示与服务器发射点共用同一张偏移表，改一处两端同时生效。
- **服务器权威**：服务器记录"当前手上持有的武器"，随实体同步信息下发（武器类别 + 下标），客户端按服务器下发的数据表现、不反查技能表；**常驻漂浮武器**由客户端按同步下来的技能槽技能 id 查技能表得到，两端结果天然一致。

**[A改]** **双方角色都初始携带攻击型技能**（可破坏珊瑚、攻击敌人），每个角色的初始武器各不相同。

**[A改]** 技能**不做分类**（近战/远程/重型分类删除），一切由配置组合表达。

**[A改]** 触发方式仅主动触发（蓄力/引导不保留；自动触发归角色被动）。

**[A]** 生效时机统一 = **等待动画攻击事件**（无"输入立即生效"分支）。

**[A改]** 多攻击事件帧的响应行为、索敌规则、子弹轨迹、发射参数、目标类型、空间归属**均不预设全局枚举维度，取决于具体技能中的设置**。

**[A改 2026-09-08]【全实体统一技能模型】技能系统对**所有实体**统一：玩家角色、防御塔、瘟疫树、僵尸等非人为操控实体与玩家使用**同一套技能逻辑**——技能存储（store）、冷却（CD）、轨迹、特效绑定模型完全一致。非玩家实体与玩家的唯一差异是**施法来源**：玩家 = 技能槽快捷键手动触发；非玩家实体 = AI 自动索敌、满足条件时触发。AI 实体的施法行为**只通过调整 store / CD / 索敌范围 / 触发条件等配置参数来调节**，不引入独立的"怪物施法系统"。store 用尽的规则同样适用于所有实体（用尽即暂时无法施放，按技能 CD 每 CD 秒恢复 1 点；非玩家单位 store = -1 表示无限制）。

## 十六、昼夜系统

**[A改 2026-09-12]【昼夜表示与同步：客户端自行推演】** 昼夜用**归一化周期时间 [0, 2)** 表示：**0 与 2 = 午夜，1 = 正午**；光照归一值 = 1 − |周期时间 − 1|（≥ 0.5 为白天，即周期时间 ∈ [0.5, 1.5)）。**方向由周期时间自身推导**，不需要单独传：< 1 正在变亮、≥ 1 正在变暗。

## 十七、死亡、复活与胜负结算

### 17.1 死亡与复活 [A]

**[A]** 复活进度系统见第十六章；玩家死亡即进入复活等待（无倒地救援）。**死亡后服务器直接摧毁该单位，复活时重新创建**（自然满血；Buff 随摧毁消失，不复活后重加；愈战愈勇由复活系统按死亡次数重新添加）。

**[A改]** 愈战愈勇：复活时按累计死亡次数叠加属性层（**暂不设上限**；后续配置"第 n 次复活 → 效果层数"）；**每次死亡清空该 Buff，复活时重新完整添加**；双方同规则；无外观表现；每层属性待定 [C]。

**[A改]** **AI 与真人玩家的所有判定完全一样**（死亡/复活/团灭/结算）。

**[A]** 防守方死亡不判负（死亡期间场上无人防守，等于让出拆塔窗口）；防守方复活时长与位置待定 [C]。

### 17.2 胜负（分数制）[A]

**[A改]** 进攻方分数 = **对守护点造成的总伤害**（2026-09-06 拍板）；进攻方击杀不计分。

**[A]** 中心守护点被摧毁 → 进攻方必然获胜（拆除量满格，立即结束对局）。

**[A改]** 防守方分数 = **守护点剩余血量 × (1 + 0.1 × 击杀数)**（2026-09-06 拍板）。

**[A]** 进攻方全灭 = 立即结算当前分数并结束对局（**不直接判负**）；若进攻方此前拆除量已过半，按分数可能判胜。

**[A]** 时间耗尽 → 双方分数比较，高者胜。

**[A改]** **不单独处理平局**（分数相同按进攻方胜处理，通常认为不会发生）。

**[C]** 击杀分在防守方总分中的占比待定。

### 17.3 对局结算 [A / C]

**[A]** 对局结束后不带出局内技能和资源；结算主要产出角色经验。

**[A改]** 角色升级所需经验（从 1→2 级起）：**50000、60000、90000、120000、160000、200000、250000、300000、360000**；获得经验 = **采集量 = 对守护点造成的伤害量**（2026-09-13 澄清：早期「守护点」曾被称作「水晶」，故此前文档写作「对水晶的伤害量」；可采集珊瑚只产出武器技能，不产生经验）。
