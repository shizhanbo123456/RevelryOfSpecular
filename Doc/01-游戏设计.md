## 一、项目概述

**[A]** 本项目为"多人非对称对抗 + MOBA 式地图攻防 + 局内技能构筑"玩法。

**[A]** 多个相对较弱的进攻方玩家，对抗防守方玩家（防守方人数不限定，见第三章）。

**[A]** 双方围绕多个外围防守目标和一个最终核心展开攻防；所有玩家一起开始、一起结束战斗。

**[A]** 玩家通过近战动作、主动触发技能直接参与战斗；局外养成只保留角色等级成长（角色随玩家等级自动解锁）。

**[A]** 尽可能减少难以感知的纯数值 Buff，强调可从画面和操作中直接理解的状态变化。

**[A改]** 标准对局推荐 4 进攻方 vs 1 防守方，但实际开发中**不限制具体人数**，双方均有人即可。

**[A改]** 单局时长 **10 分钟**。

## 二、动画与攻击事件 [A]

**[A]** 玩家输入首先请求一次攻击并播放本次攻击绑定的动作；实际伤害判定、子弹生成、投掷物脱手，在动作的指定攻击事件到达时执行。

**[A]** 一个动作可以包含一个或多个攻击事件，用于连续攻击或多段发射。

**[A]** 动画事件只表达"本次攻击到达触发时机"，具体生成哪种攻击由当前动作、当前技能和本次请求决定，不把具体技能逻辑硬编码进动画文件。

**[A改]** 动画被打断后，尚未到达的动画攻击事件不再生效——**由动画状态机处理，无需代码额外处理**。

**[A改]** 攻击上下文绑定的实现方式：每次触发时向角色动画组件传入新的事件（确保旧的事件已撤销）。各动作的攻击事件数量与用途由用户后续记录在角色动画组件中。

**[A]** 部分弹幕技能允许不播放角色施法动作；使用施法动作的技能可绑定短/中/长施法动作，并在事件帧生成子弹。

**[A改]【架构原则】** 客户端中给玩家看到的内容只需保持大致合理，**所有关键判断全部在服务器**；服务器和客户端都需要播放动画（服务器上不渲染、不实例化角色，只是空壳 prefab，用来触发动画事件）。

**[A改 2026-09-12]【动画同步】** 服务器与客户端**共用同一份动画状态机资产**，同步标识用**动画状态的完整路径 hash**（两端一致）；客户端据此定位片段，并按服务器给的**归一化播放进度**继续播放，**同一片段不重播**（让本地动画连续推进，避免每帧被拽回开头）。客户端**不需要也不传递角色类型**——播哪一套动作（女 / 男 / 僵尸…）完全由服务器决定。

## 三、游戏流程与房间 [A]

### 3.1 流程 [A]

```text
加入服务器（单个服务器 = 单个房间，无匹配功能）
→ 初始界面选择角色
→ 进入组队阶段（选角与组队同时进行，房间中可随时调整角色）
→ 双方人数均 > 0 时可开始游戏（不自动分配阵营，玩家自行商议选择）
→ 全员准备，3 秒倒计时
→ 加载阶段（客户端加载界面；逐步拉取玩家/AI 名单，加载完成的客户端才进入战斗视图）
→ 正式战斗
→ 达成胜负条件
→ 全员同时结算角色经验
→ 返回组队阶段
```

### 3.2 房间与阵营 [A]

**[A改]** 无阵营意向、无 PVP/PVE 队列、无自动 AI 补位：**房间中任意玩家可自由编辑双方的 AI 玩家数量，数量不限制**。

**[A改]** 不自动分配进攻/防守：组队时手动选择阵营；双方人数都 > 0 才能开局，否则无法开启游戏，由玩家自行商议。

**[A改]** 无手动解锁：玩家等级达标后角色自动解锁；无匹配功能，只有加入服务器。

**[A]** 无倒地救援机制；玩家死亡即进入复活等待。

## 四、阵营定位 [A]

**[A]** 多名玩家协作，单体能力弱于防守方。

**[A]** 进攻方角色 17 人，暂无角色名，统一以「进攻方0」~「进攻方16」编号指代（编号 = `EntityType.Attack` 的 `type.value`，具体角色池待定）。

**[A]** 防守角色"少而精"：每角色 = 独特主动技能 + 独特被动 + 独特大招；**不设定位标签**，玩法由玩家自行摸索。

**[A]** 防守方"能力效果池"（主动池/被动池/大招池）为设计阶段的概念；6 角色技能已定稿（见第五章），效果池中未被采用的条目转入 11.3 总表"效果池（待分配）"。

**[A]** 防守方宗旨 = 守护更多守护雕像而非杀敌（杀敌仅作为对局得分的小因素）。

**[A改]** 防守方机动性强于进攻方（机动性差异由动画/位移技能表现，**载体待重新设计**）。

**[A改]** 资源来源：**攻守双方摧毁珊瑚均可正常获得武器**（同一逻辑，见第七章）。

**[A改]** 技能使用方式：**技能槽快捷键直接触发 = 全游戏通用技能使用方式**（U I O L H Y 对应槽位 1~6，非防守方专属；2026-09-06 拍板）。

**[A改]** 每个角色都有**技能槽位属性**；防守方固有主动技能和大招**也占用槽位**。

**[A]** 僵尸相关技能（召唤小型尸潮、精英僵尸军队等）供防守方角色使用；**僵尸本体为独立阵营（Zombie），只以进攻方为敌**；"提升所有僵尸刷新时的等级"类被动为防守方阵营级增益。

## 六、防守目标 [A]

### 6.1 守护雕像

**[A]** 地图 = 3 座**贤者雕像**（分布不同路线）+ 1 座**国王雕像**（位于防守区域）；守护雕像不可采集。四座雕像的位置列表记录于**地形组件 LandscapeSpawns**（置于地形预制体内），列表前 3 个为贤者雕像槽位、最后 1 个为国王雕像。

**[A]** 国王雕像分层减伤：每座存活的贤者雕像提供 25% 减伤（3 座全存 = 75%，全毁 = 0）；国王雕像不无敌、可直接攻击，形成"先毁外围 vs 直捣王座"的战略分叉。

**[A]** 减伤状态表现为护盾叠层（75% = 3 层 / 50% = 2 层 / 25% = 1 层 / 0% = 无）。

**[A改]** 无回血原则**仅约束守护雕像**（确保进攻方进度不可逆）；水晶雕像等其他单位不在禁止范围。

**[A改]** 防守方 HUD **常驻显示每座守护雕像血量**；**无预警机制**，防守方通过血量变化自行判断哪座雕像正在被拆。

### 6.2 中立雕像（天使 / 恶魔）

**[A改 2026-10-21]** 场上同时只有一座**中立雕像**：**白天刷新为天使雕像、夜晚刷新为恶魔雕像**（按刷新那一刻的昼夜判定，刷出后不再随昼夜翻转改变）；两者属性、行为、奖励完全一致，只有外观不同（实体上用 `value` 区分：0 = 天使雕像，1 = 恶魔雕像）。

**[A改 2026-09-22]** 中立单位，双方争抢。**「攻占」= 把雕像击破**（雕像不属于任何一方，被击破后消失）：
- **归属**：把雕像**血量清零的那一次攻击的攻击者**获得「瘟疫祝福」；**被 Buff / DoT（固定数值伤害）打死的没有归属**，不给任何实体加成
- **奖励内容**：**伤害增加 75% + 伤害减免 25%**，持续 **30s**，作用于获得者**的所有技能**（含防守方主动 / 大招）
- **刷新时序**：开战后 **30s** 刷第 1 座；此后每座被击破，**60s 倒计时**结束后在候选点随机刷新一座（白天天使 / 夜晚恶魔）

**[A改]** 中立雕像为中立，不属于任何阵营，**不提供视野**。

**[A改 2026-09-08]** 中立雕像**主动攻击**：对进入攻击范围的**进攻方与防守方**单位自动索敌施放技能（中立无友方，对攻守双方均敌对，谁靠近打谁；不打珊瑚与水晶雕像）；技能走全实体统一技能模型（见 13.1），施法行为由 store / CD / 索敌范围等配置调节。

**[A改 2026-10-30]** 摧毁珊瑚即给**击杀者回血**，与掉落是否命中、命中后走了哪条分支无关：恢复量按珊瑚尺寸取 `global_variables` 的 `coral_small_regeneration` / `coral_large_regeneration`，夹到生命上限；击杀者不是玩家单位（未归属任何客户端）时不回血。

**[A改 2026-10-30]** 珊瑚刷新：**按玩家邻近动态生成**，无固定重生冷却——每秒 10 次检测，随机取一名存活玩家，在其 **[40m, 80m] 环带内随机采样位置**，被采样点须同时满足：①落在 `AssetsManager.MapSpace` 标出的合法刷新区内 ②该点 40m 内无任何存活玩家 ③与场上已有珊瑚距离 **> 1m** ④该点所在区块（40m×40m）的珊瑚平均密度 **< 0.04 个/㎡**（即每区块最多约 64 个）；四条都满足才生成，**大珊瑚概率 30%，其余为小珊瑚**。珊瑚被摧毁后不保留任何占用记录，同位置可再次被生成。刷新位置不再预先生成点位表，全部由运行时采样 `MapSpace` + `Terrain.SampleHeight` 得到。

## 九、全场僵尸 [A]

**[A改]** 僵尸刷新：场上总量上限 **30 只**；**夜间持续刷新，白天不刷新**（刷新由 cd 进度驱动，见下条）；特殊技能使数量 ≥30 时仅停止刷新，不会自动消失。

**[A改]** 僵尸刷新机制（2026-09-06 拍板）：维护一个**刷新 cd 进度**——

## 十一、状态与 Buff 系统

### 11.1 Buff 设计原则 [A]

1. 永久数值变化属于角色属性，不作为 Buff 显示。
2. 昼夜产生的阵营规则使用统一昼夜状态表达。
3. 只保留能从画面或操作中直接感知的状态；玩家无法理解的变化不做成独立 Buff。
4. 影响全局参数的被动（僵尸刷新等级等）开局一次性计算，**不进 Buff 系统**；受击类被动（白眼伯爵单次受伤上限、瘟疫使者低血挂盾）在伤害结算时即时判定，也不做成常驻 Buff。
5. 全局无回血原则**仅约束守护雕像**；其他单位的回血类效果不受此限制（如"水晶雕像缓慢回血"闲置效果）。

### 11.2 分类框架 [C 暂定]

护盾类 / 属性调整类 / 机制调整类 三类框架**暂定**，待 Buff 系统详细设计后定稿。

### 11.3 Buff 清单（总表）

> **Buff 的类型、效果、来源、特征与特效映射，只在《03-技能与Buff总表》二章维护**，本文件不重复列。
> 本策划案只保留规则：叠加语义由 effect.csv「叠加模式」列决定——**0 = 高等级覆盖低等级、相同等级刷新时间；1 = 多层分别生效、分别计算剩余时间；2 = 刷新时间并叠加等级；3 = 强制 1 级、重复添加仅取最大时间**。每个 Buff 必带等级与持续时长（无限 = 极大值）；属性修改类 Buff 只改属性不改其它状态；控制与霸体的表现由「禁止移动输入 / 禁止技能输入 / 冻结动画 / 霸体等级覆盖」四列决定，不按类型写死。

## 十六、昼夜系统

**[A改]** 白天 **90s**、夜晚 **90s**，一个完整昼夜周期 = **180s**（2026-09-12 定稿）；**黄昏 / 黎明不单独计时**——归一化昼夜模型下昼夜切换自带渐变过渡。

**[A改 2026-09-12]【昼夜表示与同步：客户端自行推演】** 昼夜用**归一化周期时间 [0, 2)** 表示：**0 与 2 = 午夜，1 = 正午**；光照归一值 = 1 − |周期时间 − 1|（≥ 0.5 为白天，即周期时间 ∈ [0.5, 1.5)）。**方向由周期时间自身推导**，不需要单独传：< 1 正在变亮、≥ 1 正在变暗。
同步只下发**三个摘要**——周期时间 + 白天时长 + 夜晚时长，客户端据此**自行推进**，服务器**不逐帧同步**（仅在战斗开始、时长/时间被改动、以及固定心跳时下发完整快照）。时长发生变化时客户端按新速率继续，**不会跳变当前时刻**。

**[A改]** 防守方复活时长 = **25s（昼夜一样）**；复活位置记录于地形组件 LandscapeSpawns（置于地形预制体内），复活时随机选取（2026-09-06 拍板）。该组件承载**固定地图点位**（守护雕像/水晶雕像/中立雕像/双方出生-复活位置）。该组件在**服务器与客户端场景各挂一份**，使用同一套点位，**服务器侧只提供点位、不含贴图与图形表现**（2026-09-10 补充）。**双方的「出生点」与「复活点」合并为同一个位置列表**——一方配 n 个位置，开局出生与死亡复活都从中随机取一个，不做去重（2026-09-11 拍板）。点位以**场景锚点（Transform）**记录以便手动拖动调整。珊瑚刷新点与僵尸出生点不记录锚点，运行时采样 `AssetsManager.MapSpace` 合法刷新区（2026-10-30）。锚点必须属于地形预制体，服务器那份才能取到。

**[A]** 昼夜的**全局影响清单**限定为三条：①复活进度速率 ②僵尸刷新 cd 进度（夜间积累、白天不积累，见第九章）③**夜间自动为进攻方添加 Debuff = 无法获得来自队友的小地图视野**。其余一切昼夜相关效果全走技能/Buff。

**[A改]** 昼夜**不影响主动技能**；只有部分**被动技能**与夜晚相关。

**[A改]** "夜间拆雕像减速"后续依靠防守方为守护雕像提供 Buff 实现（非全局规则）。

## 十七、死亡、复活与胜负结算

### 17.1 死亡与复活 [A]

**[A]** 复活进度系统见第十六章；玩家死亡即进入复活等待（无倒地救援）。**死亡后服务器直接摧毁该单位，复活时重新创建**（自然满血；Buff 随摧毁消失，不复活后重加；愈战愈勇由复活系统按死亡次数重新添加）。

**[A改]** 愈战愈勇：复活时按累计死亡次数叠加属性层（**暂不设上限**；后续配置"第 n 次复活 → 效果层数"）；**每次死亡清空该 Buff，复活时重新完整添加**；双方同规则；无外观表现；每层属性待定 [C]。

**[A改]** **AI 与真人玩家的所有判定完全一样**（死亡/复活/团灭/结算）。

**[A]** 防守方死亡不判负（死亡期间场上无人防守，等于让出拆雕像窗口）；防守方复活时长与位置待定 [C]。

### 17.2 胜负（分数制）[A]

**[A改]** 进攻方分数 = **对守护雕像造成的总伤害**（2026-09-06 拍板）；进攻方击杀不计分。

**[A]** 国王雕像被摧毁 → 进攻方必然获胜（拆除量满格，立即结束对局）。

**[A改]** 防守方分数 = **守护雕像剩余血量 × (1 + 0.1 × 击杀数)**（2026-09-06 拍板）。

**[A]** 进攻方全灭 = 立即结算当前分数并结束对局（**不直接判负**）；若进攻方此前拆除量已过半，按分数可能判胜。

**[A]** 时间耗尽 → 双方分数比较，高者胜。

**[A改]** **不单独处理平局**（分数相同按进攻方胜处理，通常认为不会发生）。

**[C]** 击杀分在防守方总分中的占比待定。

### 17.3 对局结算 [A / C]

**[A]** 对局结束后不带出局内技能和资源；结算主要产出角色经验。

**[A改]** 角色升级所需经验（从 1→2 级起）：**50000、60000、90000、120000、160000、200000、250000、300000、360000**；获得经验 = **采集量 = 对守护雕像造成的伤害量**（2026-09-13 澄清：可采集珊瑚只产出武器技能，不产生经验）。
